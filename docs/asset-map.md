## 建议归属

这是待批准的工作模型，不代表资产已经迁移：

- `9fields`：面向公众的品牌与产品组织。放置官网源码、公开项目、示例、SDK 和社区资料；本仓库未来优先落在此组织，建议仓库名为 `9field.org`。
- `JiuyeTongqu`：公司主体与内部工程组织。放置内部服务、运维、商业系统和不适合公开的仓库。
- `9fields.cn`：公司正式主站与企业信息的权威来源，继续由京东云承载；正式介绍、主体资质、商务联系与合规信息以此站为准。
- `9field.org`：面向品牌、产品、技术与社区的门户，由 Cloudflare 托管，优先采用静态站点与自动部署；涉及正式企业信息时链接至 `.cn`，避免维护两套权威内容。

这样划分的核心是“公众品牌”和“公司内部”分层，而不是按技术栈或人员临时分仓。

## 下一步盘点

在执行迁移或配置生产部署前，需要确认：

1. 两个 GitHub 组织中的私有仓库、团队、外部协作者、Secrets、Apps、Packages 和 Actions 用量。
2. 两个域名的注册商、DNS 权威、续费负责人、证书、邮件记录和现有子域名。
3. 京东云与 Cloudflare 的账户所有者、账单负责人、恢复方式和最少两名管理员。
4. `9field.org` 首版的目标受众、品牌资料、页面范围、语言，以及哪些正式信息应直接链接至 `9fields.cn`。
5. 官网仓库最终归属、可见性、默认分支保护和 Cloudflare 部署方式。

## 已知风险

- 仅凭公开页面无法确认私有仓库和组织配置，迁移前必须使用组织管理员视角完成清单。
- 域名、邮件 DNS 和生产流量变更可能造成不可逆中断，必须单独评审并保留回滚方案。
- `.cn` 站点可能涉及备案、公安备案或大陆访问要求；确认合规与业务用途前不做重定向或下线。
